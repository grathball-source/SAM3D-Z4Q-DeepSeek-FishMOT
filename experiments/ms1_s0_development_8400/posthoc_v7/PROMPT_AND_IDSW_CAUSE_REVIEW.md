# MS1-S0 V7 请求内容与 IDSW 增量事后审计

本审计只读已公开的 V7 请求、调用账本、恢复回放 seal、8400 帧预测与评分源；GT **仅在核对预测 seal 后**用于解释 IDSW。没有新模型调用、状态回放、改 prompt、改旧响应或改旧评分。逐请求大小、F5927 输入摘要及每条切换在 [PROMPT_AND_IDSW_AUDIT.json](PROMPT_AND_IDSW_AUDIT.json)，计算方法在 [audit_prompt_idsw.py](audit_prompt_idsw.py)。该脚本独立按 TrackEval CLEAR 的阈值和匹配顺序重算，精确得到 B0=6、B-HOLD-S0=18、B-VLM-S0=18，与已封存 [METRICS.json](../run_development_v7_recovery/public/METRICS.json)一致。

## 实际给 DeepSeek 的信息

16 个原始请求包及其文本见 [requests/](../run_development_v7_paid/public/requests/)；M/S0 都有同一段 769 字符 SYSTEM。M 的 USER 正文范围为 118,650–209,596 字符，S0 为 148,021–388,837 字符。这是**字符数，不是 token 数**。实际载荷还通过 Files API 引用匿名预测 mask 几何 PNG；M 每次 4–5 张，S0 每次 7–10 张。没有原始 RGB 颜色纹理、GT raster、公开身份编号或 native 到实际鱼身份的私有绑定。

SYSTEM 规定：A/B 是进入前两个参考身份，X/Y 是当前分离观测；群组 mask 不能同时充当两条鱼的个体测量；程序给出物理量和质量，模型不得补造缺失速度、隐藏轨迹、深度或未来观测；匿名观测保留但不直接认证身份。M 只能提出可推翻的合并过程假设，不能改 ID。S0 的 USER 把如下内容逐项写成实际 JSON 事实，并要求联合选择 `H1: A→X,B→Y`、`H2: A→Y,B→X` 或 `DEFER`：

1. A/B 进入前的合格逐帧观测、片段边界、来源版本、位置、面积、连续运动回归及残差、whole/core 深度和样本质量；风险后内容另列匿名，不拼成身份历史。
2. 合并期间群组测量、残片、风险与可见性区间，以及图中每个角色到帧局部 `fact_id` 的绑定。群组位置、深度不当作 A/B 双重个体证据。
3. 截至首个分离帧 q 的 X/Y 观测、可用的时间对齐两候选边测量、深度质量、缺失项；单点 post 速度明确为 `UNKNOWN`。
4. 先前 M 的返回以 `MODEL_HYPOTHESIS` 身份随 S0 再传一次，可被推翻；候选映射与图像索引也显式传入。S0 只允许使用 q 及之前的信息。

**F5927（ID 1/7 疑似合并）的实际 S0 包是一个重要限制。** [请求文本](../run_development_v7_paid/public/requests/MS1-F5927-S0.json)有 206,167 字符、10 张几何图，截止 F5939。A 有 F5848–F5877 的 30 条合格进入前观测，末端中心 `[360.0,99.5]` px，回归速度大小约 5.965 px/s。**B 合格进入前观测为 0，运动 `UNKNOWN`**；F5897–F5926 的 60 条风险观测保留为匿名证据。F5927–F5938 有 12 帧群组测量和 12 条其他匿名观测。F5939 的 X/Y 各只有一条观测，中心分别 `[305.5,84.5]` / `[356.5,97.5]` px，post 运动均 `UNKNOWN`。因 B 缺合格片段，程序提供的双边成对测量列表是 `[]`，没有把匿名路径冒充 B 的真实运动。M 假设在包中，但它不是传感器事实。[原调用账本](../run_development_v7_paid/public/CALL_LEDGER.jsonl)对 F5927-S0 只有 START、没有 END 或响应，因此无法确认服务端是否实际处理了这份 S0 文本，更不能为它写出模型选择。

## IDSW 的精确分解

TrackEval CLEAR 在 IoU 达到 0.5 的匹配上，比较一条 GT 鱼**本次**匹配到的公开跟踪 ID 与**上次被匹配**时的 ID；中间有空帧也保留此前 ID。[本实验评分入口](../score.py)使用的本地 TrackEval `metrics/clear.py` 采用此规则。因此只发布一帧负数临时 ID，也可能产生进入和退出两次切换。

冻结的保护逻辑在首次疑似时立即开启；若仍有一个旧成员的残片，`_temporary_id` 为它分配 `-1000000` 一类负数 ID，`ProtectedStableReturn.step` 把该映射放入当前帧 `ids`，回放随后首次发布。代码中的 `preview_only_not_published` trace 字段不能改变实际发布结果。[临时 ID 分配](../merge_split_manager.py)、[发布入口](../replay_v7_recovery.py)。结果是内部“匿名证据”占用了评分器可见的持久跟踪 ID 槽位。

| 疑似事件 | GT 鱼 | 公开 ID 路径 | 临时 ID 首次被匹配 / 回到原号 | 最终事件状态 |
| --- | ---: | --- | --- | --- |
| F1152 | 1 | `0 → -1000000 → 0` | F1172 / F1274 | 已解决，无额外改号 |
| F2145 | 5 | `4 → -1000001 → 4` | F2145 / F2146 | **取消** |
| F4057 | 4 | `3 → -1000007 → 3` | F4057 / F4071 | 已解决，无额外改号 |
| F4485 | 6 | `5 → -1000008 → 5` | F4485 / F4501 | 已解决，无额外改号 |
| F4519 | 1 | `0 → -1000009 → 0` | F4521 / F4524 | HOLD 未解决，回退 B0 |
| F5303 | 6 | `5 → -1000010 → 5` | F5303 / F5304 | **取消** |

八组往返各计 2 次，共 **16 次 HOLD/VLM 独有切换**。其中三个最终取消的疑似事件 F2145、F5303、F6052 已经贡献 **6 次**，说明仅事后取消并不会抹掉首次发布。保护机制同时消除了 B0 原有的四次切换：GT 1 的 F1274/F1327 `0→6→0`，GT 3 的 F8035/F8054 `2→8→2`。F5933/F5939 两次为 B0、HOLD、VLM 共有。故精确关系是 `B0 6 − 消除 4 + 新增 16 = HOLD/VLM 18`，净增 **12**。每条帧号、GT、native mask、旧/新公共 ID 和 IoU 均在 JSON 中。

## 归因边界

**这 12 次净增不是 DeepSeek 的分离关联选择造成。** B-HOLD-S0 与 B-VLM-S0 的整段输出逐帧一致、IDSW 同为 18；临时 ID 在疑似/合并阶段就被发布，M 按协议不改身份，S0 到 q 才能决策，无法回写已发布的帧。F4519 虽有模型内部 stage/commit，公开 ID 与 HOLD 相同；F5927-S0 结果未知，按冻结规则回退。输入侧的 B 历史缺失与发布侧的临时 ID 切换是两个不同限制，不能把后一问题归咎于模型推理能力。

若要针对 IDSW 继续修复，目标是**让疑似及匿名群组阶段的发布身份合同与内部保护状态一致**，并覆盖随后被取消的事件；不能只在评测器里忽略负数 ID，也不能用未来帧重画已发布结果。本审计没有实施这一修复或开启新试验。
