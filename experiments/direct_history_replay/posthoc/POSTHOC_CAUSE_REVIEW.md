# DeepSeek 介入负结果的事后因果复盘（2026-09-27）

## 判定与证据边界

本报告只复盘已封存的 Z4Q 验证段 2,888 帧实验。**工程闭环已完成；这一次冻结的 DeepSeek 关联决策造成全段身份指标下降，应停止该版本。**四个正式请求均正常返回、解析有效；B03 和 B04 的选择确实通过 `Bridge.stage` 并进入 `commit_once`，后续帧使用修改后的状态。B01、B05 是 KEEP，没有新增事务。没有新的模型调用、训练、GT 引导选择、提示词修订或隐藏测试集评价。

根因不能缩写为“深度无用”或“模型看错了图”。两个错误提交发生在**跨接触身份不可直接观测**时：B03 的外形、水平顺序和整鱼端点深度恰好支持错误交换；B04 的端点深度甚至强烈支持错误交换。模型把这些非身份不变量当成足够的身份解释，且在 B03、B04 的理由中分别出现可与发送数值核对的方位/速度叙述错误。合法事务检查只保证状态可执行，不保证物理身份正确。全段损失来自错误公开 ID 在较长时间内延续、跨窗口破坏关联，而非掩码改变。

结论适用于**已曝光、固定四个离线事件机会与当前决策策略**，不是自动困难触发的效能结论，也不是完整事件历史或深度信息理论上无效的结论。输入中的 `pair_contact_predicted=true` 仍只是 `PREDICTION_DRIVEN_CONTACT_PROXY`；q 和案例来自既有离线清单。

## 核验方法与全段因果分解

原实验的 [预测封存](../public/PREDICTIONS_SEALED.json)、[四个事件](../public/EVENTS.json)、[原始回答](../public/responses/B03.json)、[官方评分](../public/METRICS.json) 和 [评分来源](../public/SCORE_PROVENANCE.json) 均保持只读。新的 [B03-only 回放](replay_b03_only.py) 使用同一原始观测、深度特征和现有 Bridge，在第 377 帧执行原已封存的 B03 事务，然后不执行 B04；不读取 GT。原 B01/B05 均为 KEEP，省去它们的模型调用并不改变该状态回放。其 [封存](B03_ONLY_SEAL.json) 记录预测 SHA-256 `d32ac30845a57fbdf5399fc435c071517e11dda47d2bfece778378011cee38e6`。前 2,637 帧与原 B1 逐帧完全一致，2,888 帧的掩码也完全一致；B04 之后仅 251 帧的公开 ID 不同。

封存后，独立 [评分脚本](score_ablation.py) 在实验室服务器使用原 TrackEval scorer、相同 assignments/GT/match 哈希，对 B0、B03-only、完整 B1 评分。[逐项结果](COUNTERFACTUAL_METRICS.json) 精确复现旧 B0/B1 的全部官方指标。

| 2,888 帧指标 | B0 原 Z4Q | 仅 B03 | B03＋B04，即原 B1 | 仅 B03−B0 | 加入 B04−仅 B03 |
| --- | ---: | ---: | ---: | ---: | ---: |
| IDF1 | 80.697587 | 78.913062 | 77.667372 | **−1.784524** | **−1.245691** |
| HOTA | 69.243869 | 66.507085 | 66.357032 | **−2.736784** | **−0.150052** |
| AssA | 60.074321 | 55.406352 | 55.152279 | **−4.667970** | **−0.254073** |
| IDSW | 9 | 10 | 12 | +1 | +2 |
| FP / FN | 298 / 423 | 298 / 423 | 298 / 423 | 0 / 0 | 0 / 0 |

这是**顺序条件消融**：B03 的增量是在 B0 上计算；B04 的增量是在已经提交 B03 的分支上计算。不能将 B04 当作从 B0 独立运行的事件。全段原 B1−B0 为 IDF1 −3.030215、HOTA −2.886837、AssA −4.922042、IDSW +3。两次提交均对全段指标有负增量，B03 占 HOTA/AssA 下降的主体；B04 又降低 IDF1 并增加两次 IDSW。

**为什么分窗评分看似没有损失？**第 377–2637 帧，“仅 B03”相对 B0 是完整的公开 ID `1↔5` 置换；第 2638–2888 帧，原 B1 相对“仅 B03”是完整的 `4↔5` 置换。[逐帧置换核验](CLAIM_AND_MAPPING_AUDIT.json) 分别覆盖 2,261 与 251 帧。TrackEval 若只在这些窗口内重新评分，可重新配对局部 ID，因此 B0/仅 B03 在中窗同为 IDF1 84.70875、HOTA 72.02191；仅 B03/B1 在尾窗同为 IDF1 91.08781、HOTA 81.74586。跨窗口放回整段，身份连续性被破坏，损失显现。不能用单个尾窗的相同分数否定全段负效应，也不能将窗口指标相加解释为全段指标。

[事后匹配计数](MATCHED_ID_COUNTS.json) 进一步定位了换名作用：中窗 B0 的公开 5 对物理身份 5 有 2,259 次匹配，B03 后这些匹配全落到公开 1；公开 1 对物理身份 2 的 967 次匹配则转到公开 5。尾窗若只保留 B03，公开 5 对身份 6 有 251 次、公开 4 对身份 2 有 244 次匹配；加入 B04 后，这两组分别转到公开 4 与公开 5。这是匹配掩码的计数，不能直接相加推算 TrackEval，但具体显示了“局部看似修正某个固定 ID，整段反而变差”的状态路径。

## 四个选择的事后物理映射

H1/H2 的 X/Y→A/B 定义**每案不同**，因此 [核验程序](audit_claims.py) 按实际请求读取映射，再用封存后才读取的来源 GT 在进入前参考与 q 的物理身份上逐边比较。下表的“对/错”指**该包的局部前后物理解释**，不是相对 B0 的 TrackEval 增量。

| 案例 | q | 模型原选 | 该案模型选中的映射 | 局部参考→q 事后 GT | 动作及解释 |
| --- | ---: | --- | --- | --- | --- |
| B03 | 377 | H2 | X←B，Y←A | A=2，B=5；X=2，Y=5 | 错误 COMMIT；正确为 H1 |
| B01 | 1498 | H2 | X←A，Y←B | A=2，B=6；X=6，Y=2 | 错误 KEEP；没有新增事务，不能计为本轮负增量 |
| B05 | 2580 | H2 | X←B，Y←A | A=1，B=2；X=2，Y=1 | 正确 KEEP；没有新增事务 |
| B04 | 2638 | H1 | X←B，Y←A | A=6，B=2；X=6，Y=2 | 错误 COMMIT；正确为 H2 |

四次原始解释在此事后局部 GT 定义下为 **1 正确、3 错误**；实际状态事务为 **0 正确、2 错误**。这两个分母不能互换。B01 的错误 KEEP 可能遗漏一个局部正确映射，但该选择没有改变本次 B1 状态；未运行 B01 的替代闭环，不能声称其潜在收益。B05 的正确 KEEP 也不能据此宣称方法安全或改善。

### B03：多个表面线索一致，却仍指向错误身份

- 进入前 A 参考帧 306、B 参考帧 315；q=377，时间间隔分别 2.365 s 和 2.065 s。风险期间的 520 条表格行是匿名事件证据，`first_identity_reappearance=UNKNOWN`，没有认证的 A/B→X/Y 身份路径。事后 GT 显示 X 仍为 A 的物理身份 2，Y 仍为 B 的物理身份 5。模型选择反向的 H2，Bridge 将 native 1→公开 5、native 5→公开 1。
- [模型原文](../public/responses/B03.json) 说 A 与 Y 都狭长、B 与 X 都较宽；从发送端点框看，这种形状相似**确实存在**，但鱼的朝向、掩码形态会在交互后改变，不能单独当作身份不变量。模型还说进入前“B 在 A 右上方”且此顺序保持。发送的 `RELATIVE-PRE` 为 B−A=(+35.538,+5.102) px；图像 y 向下，所以 B 是右**下**方，且垂直差仅约 5 px。q 时 X−Y=(+45,−21.5) px，是右**上**方；水平符号延续，垂直符号没有延续。这个方位描述与实际表格不符，但小垂直差本身不是独立判错证据。
- 用发送端点的**整鱼**中位深度做简单绝对差求和，错误 H2 为 6.98 mm、正确 H1 为 12.13 mm；换用同一包的**核心**中位深度，H2 为 34.66 mm、H1 为 13.12 mm。两种真实测量给出相反排序，B 的整鱼有效比例 0.784、核心 0.694。该计算只是描述性端点对照，非预注册概率模型，也不能跨匿名间隔补出真实路径。它说明本案不是“有清晰深度真值却被模型忽略”，而是线索冲突时仍过度承诺交换。
- 这次 `1↔5` 在随后 2,261 帧维持为纯公开 ID 置换。它把大量原本属于公开 5 的物理身份 5 写到公开 1，同时把物理身份 2 写到公开 5，破坏全段关联；不是一次只影响 q 的本地标签错误。

### B04：精确的端点深度匹配误导了长间隔关联

- A 最后合格片段为 2537–2544（8 帧），B 为 2495–2525（31 帧）；q=2638，间隔分别 3.132 s 与 3.765 s。X/Y 的最终合格片段都只有 2632–2638（7 帧）。风险表有 805 行，但事件合同将其中联系记为匿名，身份重现仍为 UNKNOWN。B04 基于 B03 已改变的 B1 状态执行，而非独立原 Z4Q 状态。
- [模型原文](../public/responses/B04.json) 偏向 H1 的深度部分有真实数值基础：A 整鱼 831.693 mm 对 Y 831.671 mm，B 777.559 mm 对 X 797.513 mm；错误 H1 的端点绝对差和仅 19.98 mm，正确 H2 为 88.29 mm。核心深度同样偏向错误 H1（41.75 对 107.18 mm）。但这里是 `pipeline_mm_unverified_water_surface` 测量；有效比例高表示该帧有数值，**不表示跨 3–4 s 接触间隔的鱼体深度恒定或身份已被确认**。B 的末帧整鱼 MAD 为 23.316 mm，已与 B→X 的约 19.95 mm 差同量级。
- 理由又称 A “近竖直向下/慢速”延续为 Y。发送的 A 速度为 (−13.933,+110.049) px/s、速率 110.927；Y 为 (+87.823,+25.739) px/s、速率 91.517，主要向右，相比本包 B 的 42.176 与 X 的 38.297 也不能称慢。B 与 X 的短片段速度方向倒较接近。模型的方向/速度措辞与实际数值不一致；然而 GT 证明正确身份确实发生了不能由这些端点线性外推解释的运动，不能再把某条假设路径写成已观测事实。
- 事后参考 GT 为 A=6、B=2；q 为 X=6、Y=2，所以局部物理映射 H2 正确，H1 错。另一个容易混淆的层次是：B04 时 A 的 B1 公开 ID 为 5，但公开 5 的全段固定参考是 GT5；B 的公开 ID 为 4，但公开 4 的固定参考是 GT6。故局部前参考与全段公开 ID 语义**已经不一致**。H1 把 X→公开 4，恰好使 X=GT6 在固定 ID 表下获得 251 次“改善”，却把 Y→公开 5，并切断原有长序列的 ID 对应。旧 [固定 ID 逐帧审计](../public/FULL_TIMELINE_HARM_AUDIT.json) 的 967 次伤害、251 次改善是 B1 相对 B0 的个体计数，既不是两事件各自的贡献，也不能替代全段 IDF1/HOTA。顺序消融证明 B04 在 B03 条件下仍造成净负增量。

### B01 与 B05：无事务不等于判断可靠

B01 的 A 进入前只有第 1314 帧一条合格观测，速度明示 `UNKNOWN`；到 q 已间隔 6.131 s。模型却把 A→X、B→Y 描述成“测得的交互后连续轨迹”，实际没有跨风险认证链；事后正确为 X←B、Y←A。它恰好选择了 B1 当前映射，所以 KEEP。B01 的两种假设使用整鱼端点深度的简单绝对差和**同为 60.62 mm**，核心也同为 85.56 mm；端点深度不足以解释模型的确信。

B05 的 H2 事后局部正确且 KEEP，但 Y 的 q 后合格片段仅 2 帧、速度 `UNKNOWN`。模型把匿名接触风险行叙述为“连续连到”具体身份，超出了这些行的认证范围。这里整鱼端点深度反而偏向错误 H1（28.21 mm，对正确 H2 的 73.77 mm）；B05 的正确选择不能证明深度匹配规则可靠。B01/B05 与 B04 共用相邻时段和部分参考，四次请求并非四个独立随机样本。

## 归因、限制与下一步

1. **已排除的主要工程解释：**四次返回均有效，原封存/哈希绑定、真实 Bridge 提交、B0 精确复现、官方 GT/TrackEval 同源核对通过；所有分支 2,888 帧掩码相同，FP/FN 不变。不是模型未发送、解析失败、GT 挑动作、只改输出文件或新检测误差导致该负增量。
2. **直接的决策错误：**B03 和 B04 在身份不可见区间把外形、相对顺序、端点深度/短时速度升级为完整身份结论；一处方位、一处速度表述可与输入直接反证。B01 也作出错误局部解释但没有行动。提示词虽允许 DEFER，本次没有把线索矛盾与风险间隔转换为弃权。
3. **放大机制：**Bridge 的合法性与质量门槛允许这两个原子事务；错误公开 ID 继续进入自身状态。B03 影响从 377 到末尾的全段身份连续性，B04 在其基础上改写最后 251 帧。全段关联指标因此下降；短窗口重打分会掩盖跨窗口破坏。
4. **尚不能判定：**哪种输入模态在总体上必要、若使用不同数值基线/弃权门槛会怎样、自动困难触发与未曝光数据的效应，以及只执行 B04 从 B0 起步的独立效果。此处的端点绝对差没有相同全历史的冻结数值对照，不能拿它证明 VLM 的必要性或不必要性。不能据此废止事件历史/深度研究方向。

**一个下一步：**在新的、与这四案 GT 隔离的事件集上，先冻结“参考身份语义一致性＋跨风险证据不足时弃权”的提交门槛，再做成对的完整状态回放；不在本次已曝光四案上滚动调到通过。

## 复现与产物

- `replay_b03_only.py`：本地已有 Z4Q 输入与 Bridge，零 API、零 GT；输出 `predictions_b03_only.jsonl.gz` 与 `B03_ONLY_SEAL.json`。
- `score_ablation.py`：实验室服务器原 scorer/TrackEval、已核验 assignments/truth/matches；输出 `COUNTERFACTUAL_METRICS.json`。先封存预测，再打开 GT。

- `audit_claims.py`：在独立评分后，按每案实际 H1/H2 映射绑定公开请求、回答和紧凑 GT 结果；输出 `CLAIM_AND_MAPPING_AUDIT.json`，也逐帧检查两段置换。
