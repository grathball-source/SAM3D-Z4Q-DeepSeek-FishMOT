## 比较归因：独立 PID 是新的底座

`runner.py:18` 分别建立真正的原版 `Bridge` 和两个新的 `Identity`。新 PID 臂既不继承 `StableReturn`，也不消费原 Z4Q 的已接受恢复作为身份裁决。`identity.py:116` 之后由本臂连续映射、当前占用和新的全局矩阵决定发布；原 native 整数重现没有夺回公共身份的特权。这确实解除了一类原生命周期障碍，但也移除了原 Z4Q 的其他能力。

原 D1 在 `online/closed_loop_2888/z4q_source/source/sam3_depth_failure_repair_20260917/repair_controller_r3.py:45` 起结合最近丢失、接触伙伴、真实 whole 深度、伙伴排歧、存活者自身兼容性与连续五次确认。原 `controller_z2.py:41` 的 BirthRefine 使用 core/whole 双视图、whole 显式矛盾、当前存活者自身与交叉比较，以及至少一名可靠存活者；`controller_z4.py:22` 还提供近期实际孤立 core 证据。DS31 重用了一些窗口、dummy 和 margin，但没有重用这些完整准入路径；旧身份匹配通过一次全局 margin 后便立即提交。它也用十点 OLS、掩码平移和 0.6/0.4 的掩码/距离代价替换了原运动代价。

因此，`PID_MOTION − Z4Q_FROZEN` 是身份生命周期、候选、运动、确认及原深度规则被移除等共同改变的净结果；`PID_DEPTH − Z4Q_FROZEN` 是整套新策略的净结果。两者都不能解释成单独的深度效果。`PID_DEPTH − PID_MOTION` 才是新 PID 底座中的动态深度模块增量，包括其后续自身状态传播。

DS30 已封存的事实说明原 Z4Q 的收益必须作为真实对照保留：FishSA 开发原 Z4Q IDF1 为 99.333472，对同源 SAM3 的增量为 8.020185；已曝光验证为 80.697587，增量 4.241143。DS30 还实际保留了 F3902 的 native7→public0 出生恢复。与此同时，DS30 的 Feeding 汇总中原 Z4Q 相对 SAM3 的 HOTA/AssA 更低、IDSW 多24，故不能把原策略描述为所有来源都更好。若新 PID 层失去原 D1/BirthRefine 的成功机会，不能把这项损失归咎于新增 WLS 深度；若恢复效果变好，也不能全部归功于深度。

## 本轮打开的机会，与仍关闭的机会

DS30 的 50 个 q 中，32 个没有双身份共时 pre，5 个缺精确参考，只有2个非null深度，且都在选择阶段 DEFER。它没有进入 stage，所以其零新增提交不能全部解释成 native-return veto。DS31 对每个 PID 单独保存可靠深度片段并按各自时间外推，移除了必须双 pre 共时的要求；每帧联合关联也增加了 q 之外的机会。但这只是代码上的机会变化，实际覆盖、真实提交和正确性均须由封存后的证据证明。

`identity.py:127` 仅让 established、有运动片段且最后 clean 未超过12秒的 PID 进入候选。普通新身份需经过五个连续 clean 观测，同时等到本 source generation 已存在至少6秒，才会 established（`:178`）；第一帧 source 除外。这里的6秒实际用于延后新身份锁定，代码没有给每条重接边单独设置“出生满6秒立即禁止”的门。若一直缺乏五点 clean，provisional source 可继续参与之后的匹配；source 重现也会重置 generation 和 birth 时间。故不能把它描述为与原 D1 首次合格窗口完全相同的六秒候选截止。

若已建立的身份经历风险之后，当前 source 保留旧 PID 但未被矩阵重新接受，`:171` 会禁止它刷新旧参考并继续置 risk。源码没有 I3 的独立 reanchor 逃生路径。于是可靠观测可能长期沿用发布 PID，而 clean motion/depth 保持陈旧，直至超过候选寿命；这项保守限制可能牺牲后续关联机会。当前版本通过报告衡量，不在本次运行中修补。

## V1 工程错误已修复；组保护不等于物理恢复成功

本次静态审计发现 V1 的真实工程错误：原成员 source 和 group source 被加入 risk，但活动组的全部成员 PID 没有整体排除出候选。若一个成员 PID 当前缺席，清楚的新 outsider source 可以在 q 尚未出现时通过普通 Hungarian 接回它，并作为 trusted source 更新目标 bank。`group_records.individual_history_updated=False` 当时不能证明整组银行被冻结。该路径违反组历史隔离契约，不能作为一种可接受的科学消融。

主任务据此停止自身 V1 进程，在评分和物理参考读取前归档全部部分产物、源码与原冻结到 `engineering_attempts/v1/`，没有将其当作完整方法结果。V2 的 `identity.py:113–115` 收集全部仍活动组的 `protected` PID，对任何当前指向这些 PID 的 source 加 risk；`:127` 在全局候选中排除全部 protected PID；`:114` 保存整 bank digest，`:193` 逐帧断言其与更新后完全相同。`checks.py:219` 专门覆盖缺席成员被 outsider 接回的反例。修复同时封住匹配入口和历史更新出口，当前问题已修复；冻结计划保留工程失败记录及 V2 的重新真实切片验收过程。

V2 保护持续到取消、超时或首次 q，然后让释放的成员参与同帧联合匹配。它保证活动组参考保持不变，并不保证每个 q 都能恢复两条旧身份：可用清楚观测、旧身份候选资格和残片占用仍会限制恢复。`events[].anchors` 是触发时记录；是否发生有效恢复应根据实际发布与封存后物理参考判定，而不是只看状态名或日志的布尔值。

q 候选使用运动可行、面积门和相对最近已记录 group mask 至少0.15的实际空间支持（`:90`），同时 donor 下一帧仍保有至少半数旧面积时取消事件（`:97`）。这减少无关观测被当作分离的机会，但 q 的这层候选定义没有单独检查 score；真正匹配仍有 `clean` 质量门。`GROUP` 确认分支仅检查是否到达规定帧（`:105`），没有要求第二帧继续观测到 group mask 或独立合并证据；下一帧 donor 取消也不覆盖所有误触发。因此“2帧确认”是有限的生命周期门，不能认证两次真实合并观测。两候选 q 分支在确认分支之前，所以事件可以记录 q 而 `confirm_frame` 仍为空；这种事件应称为疑似组的分离/取消处理，不能冒称已确认合并。

并发组只排除 PID 成员重叠，没有证明各组的当前掩码支持或候选域也互不重叠。最终矩阵和输出唯一性保护同帧一对一；它们不自动证明每个事件的成员绑定正确。组创建只要求两名不同 source PID 已有 bank（`:78`），没有额外断言两个 bank 均已 established，因此也不能把每个疑似组都描述为拥有两名成熟可靠身份。单个合并掩码若未被原 scan 或当前 neighbors 标识，面积比例门与深度混层门也不保证识别所有混鱼运动观测。可靠深度 UNKNOWN 会阻断深度片段更新，但不等于冻结所有未识别混鱼的运动更新。

## 残片、历史和深度覆盖的具体限制

同帧所有原 mask 保留，不能给同一 PID 发布两条观测。新 group owner 也只发布原 mask，并不强制把它拆成成员。旧成员残片在 q 仍占用成员 PID 时，`:128` 显式记录 `occupied_member_targets` 并阻止目标重接。首次 q 若无法同时得到两名旧身份，保留 UNKNOWN，不把一个已接回或一个受阻的目标称为有效完整物理恢复。q 之后解除组保护，这个残片可能重新进入矩阵并改变编号，另一清楚观测也可能接回旧 PID；占用是逐帧事实，不能假定永久不变。这种延迟与残片编号变化本身可影响 IDSW，而无需深度介入。

clean 更新要求同 source generation、同 PID 且相邻帧才能拼接 motion/depth_live（`:180`）；不合格深度会清空 live，而保留最近完成的可靠 depth 片段供外推。当前 query 在选择后才写入目标参考，旧片段和新片段不拼接。持久 PID 存在并不代表仍有可用运动或深度；12秒寿命、变化的 source 版本和 UNKNOWN 均会限制实际机会。

深度仅在单行几何最优与次优（含dummy）间隔不超过0.3时启用（`:144`）。这是局部行准入，不是完整全局矩阵的模糊度判断：多行抢同一目标可能全局模糊但局部行明确，深度不会启用；局部行模糊也可能已被其他行全局排歧。`depth.py:114` 要求该行所有可行 PID 都有可用历史，否则整行共同null。这避免缺历史候选获得零成本优势，也会让一名无历史竞争者关闭整行深度。dummy 的数值保持1，但有效深度可改变真实边相对dummy的margin，所以它可能影响接回/暂不接回，也可能影响两个旧身份之间的选择。

UNKNOWN 的精确退化是“相同前状态、相同候选下没有新增深度项”。在此前深度已改变过映射或历史之后，两臂自身状态可以继续不同；后续一个null帧不要求它们重新相同，不应复制 `PID_MOTION` 状态给 `PID_DEPTH`。同理，两臂完整差值不能用同帧单次边代价替代。

## 封存后报告应区分的量

`runner.py:54` 将所有 `actions` 计入 commits，而选中边可以只是已有 source 再次确认同一 PID（`previous_pid == target`）。这类动作不能全部称为新身份恢复。应分别列出维持原映射、首次旧 PID 接回、已有 PID 改接、dummy/新身份、q目标被残片占用，以及后续持续帧。

`depth_rows.active` 表示该行实际算了深度，不能代表深度改变了选择，更不能代表物理身份正确。`geometry_selected_target` 提供同状态几何选择诊断，但另一行的深度也可能通过全局竞争改变本行，直接活跃行的计数不会覆盖所有间接变化。最终科学结论需结合两条完整独立分支、逐动作实际发布、持续映射及封存后物理参考的正确/错误/UNKNOWN，而非仅依赖激活数或提交数。

若 `PID_DEPTH` 优于 `PID_MOTION` 但仍不及 `Z4Q_FROZEN`，只能说深度改善了本轮新 PID 原型，不能说取长补短已超过原方法；若两 PID 臂相同，只能说冻结机会和门槛下未观察到深度增量；若 `PID_DEPTH` 更差，应报告本配置的实际负增量及其状态传播。任何对原 Z4Q 的升降都必须同时分析共同底座改变。全部来源已曝光，L3/LW为弱预标注；代码上的逐帧因果性、深度尺度和同源指标均不认证独立泛化或真实鱼体表面深度精度。

本文不预判 DS31 结果，不以代码局限替代实际完整验收，也不从旧 DS30 的零增量推出新实验必然失败。
