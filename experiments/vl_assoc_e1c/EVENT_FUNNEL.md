The original V4 register has 185 development + 104 validation = **289** events, of which 159 + 83 = 242 reached its two-owner query and 42 + 18 = 60 had an executable old swap. `event_probe.py:122-125` excluded missing-owner reconnections by construction. These are source-register counts, not GT truth.

The independently replayed E1C-A diagnostic retained all 289 trigger episodes. It queried 164 development and 92 validation episodes (256 total, counting two queries with no generated proposal), generated 261 nonbaseline proposals, found 64 executable proposals in 62 events, and identified 14 one-owner recovery queries. Six of those recovery events had executable proposals. Seven one-owner rows selected three current tracklets, exceeding the requested two-tracklet cap; the rows and frozen code are preserved rather than silently repaired after scoring.

It could score 160/289 events (including 160/256 queried); 96 queried events remained unscorable, commonly because pre-trigger clean references were absent or query GT was ambiguous. Only `1-4:5` contained a GT-correct old swap, but the clone stage rejected it for current quality/contact. The frame-219 one-owner recovery candidates were executable but both GT-wrong; the true current native was not proposed. No executable recovery candidate was confirmed correct. `ERROR_COVERAGE.jsonl` retains every event, including all unscorable rows; it is not a full-sequence tracker error census.

Among 14 recovery queries, two were scorable and both lacked a correct executable restoration; twelve were unscorable.
