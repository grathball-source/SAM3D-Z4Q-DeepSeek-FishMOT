# B0-R single strategy change

The frozen `StableReturn` executes its written rule. This is a **method/data-transfer failure, not a proven software bug**. `DepthRepair.step` accepts a source as a D1 “new” candidate for up to six seconds after its birth and three seconds after its first eligible clean observation. A source can already have a long, uninterrupted native identity by the time that eligibility starts. `NativePrior.certificate` protects some partner edges but does not veto reconnecting the candidate itself.

At original F159, native 26 had **135** continuous preceding observations and first became D1-eligible at F137. Five D1 confirmations, plausible geometry and a 14.495 mm depth residual then assigned it to dormant public 16. The actual F159 mask matches edited GT 26; the old reference mask matches GT 16. The action wrote alias `26→16`, cleared native continuity, changed bank/previous/epochs, and affected subsequent output. F190 repeats the same class with native 30→public 8 after 25 continuous observations. Neither commit is a saved-batch boundary.

The one fixed intervention is `CertifiedNativeGuard` in [onefix.py](onefix.py). Before calling the unchanged controller, it suppresses only a D1 candidate whose existing native certificate qualifies **and** whose uninterrupted run covers two five-frame confirmation windows. It restores the temporary eligibility field before the preview state is committed. New sources may still reconnect; BirthRefine, partner rules, depth weights, thresholds, and all other state flow remain unchanged. The ten-frame condition is a pre-run semantic requirement for one full native confirmation window before the five-frame D1 decision window. It is a **NEW_HYPOTHESIS**, not a tuned or universal fix.

The prefreeze targeted test caught an overbroad one-window guard: it would have suppressed the original F194 native-38 reconnect. The final two-window rule passed that test and was then frozen for **one** full replay per source. No condition was changed after the one-fix predictions were sealed and scored.

The F159 ALLOW/VETO experiment cloned one actual pre-decision Bridge state, changed only that decision, and continued both states through original F199. A single veto changed F159 output and improved first-segment IDF1 by 0.018638 points, but D1 made the same bad reconnect at F160. That proves a one-frame veto is insufficient. The full one-fix guard changed state over many later frames and removed all four SOURCE_OLD extra CLEAR switch occurrences.

Its cost is visible on the independent SOURCE_BASELINE source: F372 and F506 have the same GT identity at the actual old anchor and current candidate, yet the guard suppresses those reconnects. F372 still adds a CLEAR switch at the publication boundary under B0; physical continuity and the switch metric must remain separate. The final policy has one more IDSW than native on that source and SOURCE_OLD HOTA remains below native. No second rule, threshold search, or model call follows this result.

The frozen Z4Q source, config, old seals, old model replies, and S0-P 8400-frame mechanism were not edited. All changes for this trial live in this new directory, apart from the handoff update.
